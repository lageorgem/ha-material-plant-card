## [0.1.0] - 2026-10-12

Unreleased — first public release in preparation.

### Added

- Material 3 Expressive plant card for Olen's plant monitor integration. Full mode is the default, as in flower-card: a header and grouped metric tiles with a small tone-coloured icon and metric name in the title row, a history label on the right, a large current value with its unit and `Ideal a–b` below it. Only real problems selected by problem settings add an error accent on the left edge and a faint error tint.
- Full-mode recorder statistics with optional string `history_period`: `24h` (default) or `7d` (example: `history_period: 7d`), selecting the window for the range, average and Min/Avg/Max. Editor: Metrics → History window; tile labels: `Last 24 h` or `Last 7 d`. The scale has ideal-bound ticks, a min–max segment coloured success inside the ideal range and error outside it, a hollow current-value ring and an average triangle coloured success in range or error outside it. Min/Avg/Max values each get an error badge outside the ideal range. Historical colours follow ideal bounds independently of problem settings; non-cumulative historical ranges include the current reading if it extends beyond recorded bounds. Refreshes every 10 minutes; `hide_history: true` disables fetching and removes the history label, historical segment, average marker and Min/Avg/Max row, keeping current values, ideal ranges, ticks and current-value rings. Measurement sensors require recorder long-term statistics with `state_class: measurement`; missing history shows `—` for Min/Avg/Max with no historical segment or average marker.
- Cumulative sensors (`state_class: total` or `total_increasing`), including the plant monitor's DLI, use daily totals for the last 7 complete days, excluding today's partial total and ignoring `history_period`. Labelled `Daily · 7 d`; the historical range, average and Min/Avg/Max summarise daily totals instead of the previous DLI `—` display. The large DLI value remains today's running total.
- Daytime-only illuminance history in full mode: optional boolean `illuminance_daytime_only`, default `true` (example: `illuminance_daytime_only: true`), excludes 0 lx (night) readings from the range, average and Min/Avg/Max. Uses Home Assistant raw history because recorder hourly statistics cannot exclude darkness, with a time-weighted daylight average. Labels `Daytime · 24 h` or `Daytime · 7 d` follow `history_period`. Current 0 lx does not extend the range and keeps the problem-setting colour instead of automatically turning error red; with default plant-driven problems, red requires a selected plant monitor problem. Editor: Metrics → Ignore darkness in illuminance history. Set `false` to restore the previous behaviour; compact mode is unchanged.
- Full-mode non-cumulative current values, rings and title icons turn error red outside ideal bounds even when problem settings do not flag them, except for 0 lx with daytime-only illuminance enabled. Cumulative current values such as DLI retain the problem-setting colour; red left accents and tints still mark only real problems.
- Compact mode with circular three-zone range gauges, icons centred on the dial, active arcs and position dots. Coloured fill follows the track's thin low/high zones, thick just-right band and the same gaps.
- Success gauge colour in range (`--md-sys-color-success`, falling back to `--success-color`), neutral on-surface-variant out of range without a problem, and error colour for problems with bold, error-coloured value text. Logarithmic illuminance scaling for lux readings with positive minimum thresholds.
- Support for moisture, conductivity, temperature, illuminance, humidity, DLI, 24-hour DLI, CO₂, soil temperature and VPD measurements supplied by the integration.
- Cookie-shaped plant photos with configurable image override and a missing/broken-image placeholder; plant name, species or problem summary, and a red error circle with a centred **!** on the photo.
- Integration-driven problems by default (low illuminance at night can remain neutral), optional out-of-range gauge problems, and measurement filtering through `problem_sensors`.
- Optional bare iOS-style battery glyph with the level number inside; error colour below `battery_warn_level` (default 10%), otherwise neutral. `battery_ok_level` is accepted but ignored for flower-card compatibility and removed from the visual editor.
- Two-line Material plain gauge tooltips: `<Metric>[ · too low/high]` and `<value> <unit> · ideal <min>–<max> <unit>`. Touch long-press (about 0.45 s), mouse hover (0.5 s) and keyboard focus show the tooltip; Escape dismisses. Normal taps open sensor more-info; long-presses do not. Photo/name and battery taps open their respective more-info dialogs.
- Shared photo size and species header in both modes, configurable measurement order and visibility, and `hide_units` defaulting to `false` in both modes. When enabled, it hides only the unit beside full-mode values, but complete compact gauge value text. Tap tiles or gauges for sensor more-info.
- Compact width-measured, balanced gauge rows when gauges do not fit one row, with the extra on the first row and the last row centred (two-row examples: 5 → 3/2, 6 → 3/3, 7 → 4/3). Compact is approximately 327 × 160 px at 327 px width with six gauges, versus flower-card's 327 × 203 px; full-mode tiles are approximately 84 px tall and a six-metric full card is approximately 327 × 614 px.
- Home Assistant visual configuration form with Metrics, Problems and Appearance sections.
- Material You theme tokens with Home Assistant theme fallbacks and reduced-motion support.
- Flower-card-compatible configuration keys, with `bars_per_row`, `show_care` and `extra_badges` accepted and ignored; independent implementation with no shared code.
- HACS/manual installation documentation, full-options and migration YAML examples, and content-addressed local deployment with SHA-256 verification before resource registration.
