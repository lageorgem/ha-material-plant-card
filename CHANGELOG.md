# Changelog

All notable changes to this project are documented here.
The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.1.0/).

## [0.1.0] - 2026-10-12

Unreleased — first public release in preparation.

### Added

- Material 3 Expressive plant card for Olen's plant monitor integration. Full mode is the default, as in flower-card: a header and grouped metric tiles with a small tone-coloured icon and metric name in the title row, a history label on the right, a large current value with its unit and `Ideal a–b` below it. Only real problems selected by problem settings add a faint red gradient tint.
- Full-mode history exclusively from recorder statistics; no raw history requests. Each metric's optional string `period` selects `today` (default), `24h`, `3d`, `7d`, `14d` or `30d` (example: `period: 14d`). `today` runs from midnight in Home Assistant's time zone to now, labelled `Today`. Measurement sensors require recorder statistics and `state_class: measurement`. History is always fetched in full mode and refreshes every 10 minutes.
- Each metric's optional string `display` selects `summary` (default) or `graph` (example: `display: graph`); both can coexist in one card. Summary shows ideal-bound ticks, a threshold-coloured min–max segment, current-value ring, average triangle and Min/Avg/Max badges. Graph shows a line coloured green inside the ideal band and error red outside, min, average (dashed) and max gridlines labelled on a small left-side y-axis, min/max triangles (red outside ideal bounds), and a latest-value ring, with no average marker or statistics row. Mouse hover or touch/drag shows the point's time and value; graph interaction does not open more-info, while the rest of the tile does.
- Graph min/max markers are points of the plotted line with a triangle at a fixed gap (up below the minimum, down above the maximum); today/24-hour graphs plot 5-minute statistics; sunrise/sunset icons sit in a band above the plot. Vertical scales fit observed values with bounds rounded to easy-to-read numbers; ideal-bound guide lines are removed. The vertical hover guide spans the full graph height. Hover bubbles stay visible while hovered and Escape dismisses them; touching or hovering a graph does not highlight or activate its tile.
- Data-ready entry animations: compact gauges sweep in their active arc and pop the dot when the value first appears, then move smoothly on updates without replaying. Graph lines draw left to right when history first arrives, before min/max markers and the current ring appear; entry motion no longer finishes before data loads or replays on later updates. Summary range bars retain their historical-span (including the 24-hour span), current-dot and average-marker entry animations. Reduced motion disables animations and movement transitions.
- Problem tiles show the hover highlight outside the graph, and the plant name has a padded hover area.
- Illuminance graphs with windows up to 3 days and `daylight_only` enabled mark golden-hour boundaries (sunrise + offset and sunset − offset) with sunrise/sunset icons above dashed vertical lines, using Home Assistant's configured location. DLI day boundaries and graph time labels use Home Assistant's configured time zone.
- Optional ordered `metrics` list with required string `type` in each entry (example `moisture`); order is display order, duplicates keep the first entry and `[]` hides all metrics. Optional per-entry `icon` (string, default metric icon; example `mdi:thermometer-lines`), `problem_trigger` (string: `plant`, `out_of_range`, `low`, `high`, `never`; default `plant`, example `low`), `period`, `days` (number, rounded and clamped to 1–30, default 7; example 14), and `display`. Triggers are independent of the monitor unless `plant`. Icon and trigger settings apply in both modes; history and display settings apply in full mode. See the [configuration reference](README.md#card-options).
- Cumulative sensors (`state_class: total` or `total_increasing`), including DLI, use maximum hourly recorded state per local day, representing DLI's daily total. `days` in the DLI entry selects 1–30 days (default 7) instead of `period`, including today's partial total. Label: `Today` for 1 day, otherwise `Daily max · N d`. Graphs show today's hourly values for 1 day (no min/max triangles), otherwise daily maxima; summary statistics describe daily maxima. Long-term statistics support 30-day windows when available. The large DLI value remains today's running total.
- Golden-hour illuminance filtering with optional `daylight_only` (boolean, default `true`; example `false`) and `daylight_offset` (number in minutes, rounded and clamped to 0–180, default 30; example 45) in the illuminance entry. Uses Home Assistant latitude/longitude; counts readings from sunrise + offset to sunset − offset. The summary range viewer uses 5-minute statistics for windows up to 7 days, with cutoffs within 5 minutes of each boundary; 14/30-day windows use whole hourly buckets. Label: `Daylight · today` by default, or the selected period. The graph line is unfiltered, including night readings; min/max triangles use daylight values. A current reading outside the window is excluded from daylight statistics and markers but remains on the graph line and is not automatically forced red. Disabling filtering hides golden-hour boundaries and uses all readings; missing location coordinates fall back to unfiltered history. Unfiltered labels are `Today` or `Last …`. Compact mode is unchanged.
- Full-mode non-cumulative current values, rings and title icons turn error red outside ideal bounds even without selected problems, except for daylight-filtered illuminance outside its window. Eligible current values extend historical extrema without changing the statistics average. DLI current values retain the problem-setting colour; faint red gradient tints mark only selected problems.
- Missing statistics show `—` in summary badges without a historical segment or average marker; current values and ideal ranges remain visible.
- Compact mode with circular three-zone range gauges, icons centred on the dial, active arcs and position dots. Coloured fill follows the track's thin low/high zones, thick just-right band and the same gaps.
- Success gauge colour in range (`--md-sys-color-success`, falling back to `--success-color`), neutral on-surface-variant out of range without a problem, and error colour for problems with bold, error-coloured value text. Logarithmic illuminance scaling for lux readings with positive minimum thresholds.
- Support for moisture, conductivity, temperature, illuminance, humidity, DLI, 24-hour DLI, CO₂, soil temperature and VPD measurements supplied by the integration.
- Cookie-shaped plant photos with configurable image override and a missing/broken-image placeholder; plant name, species or problem summary, and a red error circle with a centred **!** on the photo.
- Integration-driven problems by default (low illuminance at night can remain neutral), with per-entry triggers for either bound, low only, high only or never. Only listed, available metrics can raise measurement-specific problems; the generic `Needs attention` fallback remains when the plant reports a problem without an array-valued problems attribute.
- Optional bare iOS-style battery glyph with the level number inside; error colour below `battery_warn_level` (default 10%), otherwise neutral. `battery_ok_level` is accepted but ignored for flower-card compatibility and removed from the visual editor.
- Two-line Material plain gauge tooltips: `<Metric>[ · too low/high]` and `<value> <unit> · ideal <min>–<max> <unit>`. Touch long-press (about 0.45 s), mouse hover (0.5 s) and keyboard focus show the tooltip; Escape dismisses. Normal taps open sensor more-info; long-presses do not. Photo/name and battery taps open their respective more-info dialogs.
- Shared photo size and species header in both modes, configurable measurement order and visibility, and optional boolean `hide_units` (default `false`, example `true`). When enabled, it hides units beside full-mode current values and in graph hover bubbles, but complete compact gauge value text. Tap tiles or gauges for sensor more-info.
- Compact width-measured, balanced gauge rows when gauges do not fit one row, with the extra on the first row and the last row centred (two-row examples: 5 → 3/2, 6 → 3/3, 7 → 4/3). Compact is approximately 327 × 160 px at 327 px width with six gauges, versus flower-card's 327 × 203 px; full-mode tiles are approximately 84 px tall and a six-metric full card is approximately 327 × 614 px.
- Compact-only layout options: optional integer `gauges_per_row` (1–12, example `3`; omit for automatic balanced rows) fills rows left to right and centres the last row, falling back to automatic layout when the card is too narrow. Optional number `gauge_size` (32–96 px, default `44`, example `56`; clamped to the range) scales the dial, icon and value text. The visual editor exposes both under **Compact layout** when display type is **Compact**. Flower-card's `bars_per_row` remains ignored.
- Home Assistant visual editor with top plant, name, battery and display-type fields, an Appearance section, and a Metrics list. Add from types not yet added, drag to reorder, edit per-entry settings or delete without confirmation. First list edit converts legacy `show_bars` to `metrics`.
- Material You theme tokens with Home Assistant theme fallbacks and reduced-motion support.
- Flower-card-compatible configuration keys: `show_bars` selects types when `metrics` is absent; `bars_per_row`, `show_care` and `extra_badges` are accepted and ignored. Independent implementation with no shared code.
- HACS/manual installation documentation, full-options and migration YAML examples, and content-addressed local deployment with SHA-256 verification before resource registration.
